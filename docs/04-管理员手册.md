# 知伴 · 管理员手册

面向使用者本人（单机单人，你既是用户也是管理员）。覆盖：模型切换、日志、备份恢复、升级、数据迁移。

---

## 1. 模型与端点管理

### 1.1 切换模型（无需改代码）

**设置 → 对话模型**，改 `base_url` / `模型名` / `API Key` 三项 → **保存** → **测试连接**。

- 支持任意 **OpenAI 兼容**端点（DeepSeek / 智谱 / 百炼 / SiliconFlow / Ollama / vLLM …）
- 可随时切换，配置保存在本机 `data/zhiban.db` 的 `settings` 表，**加密存储**
- 兼容清单见 `docs/05-模型兼容列表.md`

### 1.2 嵌入模型（影响检索质量）

| 配置 | 效果 |
|---|---|
| 不配置（`provider=auto`，推荐给新用户） | 自动降级：内置本地嵌入 → 纯关键词检索，**始终可用** |
| 配置云端 `/embeddings` | 语义检索更准，需要网络与 Key |

> 换嵌入模型后，**旧文档需要重新解析**（`POST /api/documents/{id}/reparse`），
> 因为不同模型的向量维度与语义空间不同，混用会降低检索精度。

### 1.3 完全离线运行

1. 装 [Ollama](https://ollama.com/)，`ollama pull qwen2.5:7b`
2. 设置：`base_url=http://127.0.0.1:11434/v1`，模型名 `qwen2.5:7b`，Key 留空
3. 断网后可用：上传/解析/检索/问答/生成/记忆/语音输入/本地朗读

**代理行为**：外部端点会使用系统代理（`HTTP_PROXY` 等环境变量）；**回环地址
（127.0.0.1 / localhost）一律直连，绝不走代理**——这是刻意的，否则装了
Clash/v2rayN 的机器会连不上本地模型。如需强制全局禁用代理，设环境变量
`ZHIBAN_DISABLE_PROXY=1`。

## 2. 密钥安全

| 项 | 说明 |
|---|---|
| 存储位置 | `settings` 表，Fernet 加密（主密钥在 `data/secret.key`） |
| 是否下发前端 | **否**。接口只返回 `api_key_set`（布尔）与 `api_key_masked`（如 `sk-****abcd`） |
| 是否进日志 | **否**。日志过滤器会实时脱敏；`sk-`、`Bearer`、`api_key=` 等模式一并兜底 |
| 丢失后果 | 删除 `data/secret.key` 后，已保存的 Key 将无法解密，需重新填写 |

**验证方法**：配置一个假 Key 后，对 `data/logs/` 全目录搜索该明文，命中应为 0。

## 3. 端口与进程

| 项 | 说明 |
|---|---|
| 默认端口 | `8760`，被占用则顺延到 `8770` |
| 实际端口 | 写在 `data/runtime.json` |
| 监听地址 | **仅 `127.0.0.1`**，不对局域网开放 |
| 退出方式 | 关闭应用窗口即优雅退出（数据落盘、端口释放） |
| 数据库模式 | SQLite WAL；正常退出会执行 checkpoint |

## 4. 日志

- 位置：`data/logs/zhiban.log`，**JSON Lines** 格式
- 级别：默认 `INFO`，可用环境变量 `ZHIBAN_LOG_LEVEL=DEBUG` 调整
- 内容：文档解析起止、检索耗时与命中数、LLM 调用耗时、引导式状态迁移、ASR 耗时
- **不含**：API Key、用户文档原文全文（只有统计值与片段长度）
- 定位问题的推荐顺序：先看 `level=ERROR` → 再看同 `ts` 的上下文 → 结合 `extra` 字段

## 5. 备份与恢复

### 5.1 一键备份

```powershell
powershell -ExecutionPolicy Bypass -File scripts\backup.ps1 -Dest D:\backup
```

产物是带时间戳的 zip，内含 `zhiban.db`（会先 checkpoint 保证一致）、`files/`、`exports/`。
**不含** `secret.key` 与模型文件（模型可随时重新下载；如需连密钥一起备份，加 `-IncludeSecret`）。

### 5.2 恢复

```powershell
powershell -ExecutionPolicy Bypass -File scripts\restore.ps1 -Zip D:\backup\zhiban-backup-xxxx.zip
```

> 恢复前请先关闭知伴。若备份时**没有**包含 `secret.key`，恢复后需重新填写 API Key
>（资料、会话、记忆不受影响）。

### 5.3 整包迁移（最简单）

直接把整个 `知伴/` 文件夹拷到新位置/新机器，双击 `知伴.exe` 即可，数据原样带过去。

## 6. 升级

1. 备份：`scripts\backup.ps1`
2. 用新版文件夹替换旧版（**保留** `data/` 目录即可保留全部数据）
3. 启动后程序自动执行数据库迁移（版本号记录在 `schema_meta` 表，向前兼容，不丢数据）

> 回退版本前请先恢复备份。

## 7. 数据清理与磁盘占用

| 路径 | 内容 | 说明 |
|---|---|---|
| `data/zhiban.db` | 主库 | 删除某文档会级联删其切片与向量 |
| `data/files/` | 上传的原始文件 | 删除文档时同步删除 |
| `data/exports/` | 导出产物 | 可整目录清空，不影响功能 |
| `data/logs/` | 日志 | 可定期清理 |
| `data/browser-profile/` | 界面窗口的浏览器缓存 | 可删除，重启后重建 |

## 8. 常见运维问题

| 现象 | 处理 |
|---|---|
| 启动即闪退 | 看 `data/logs/zhiban.log` 末尾；多为端口全被占用或 `data/` 无写权限 |
| 问答返回 2001 | 模型端点不通；用「测试连接」定位，检查 Key/网络/模型名 |
| 检索结果变差 | 最近是否换过嵌入模型？→ 重新解析文档 |
| 语音识别报 4000 | 模型文件缺失；运行 `scripts\download_models.ps1` |
| 磁盘涨得快 | 通常是 `data/files/`（原始文档）与 `exports/`，按需清理 |

## 9. 环境变量一览（可选）

| 变量 | 作用 |
|---|---|
| `ZHIBAN_DATA_DIR` | 覆盖数据目录（默认程序目录内 `data/`） |
| `ZHIBAN_PORT` | 覆盖首选端口 |
| `ZHIBAN_LOG_LEVEL` | 日志级别（默认 INFO） |
| `ZHIBAN_DISABLE_PROXY` | 置 `1` 强制所有请求直连（不走系统代理） |
| `ZHIBAN_LLM_API_KEY` | 临时以环境变量提供 Key（优先级高于设置页，供 CI 使用） |
