# 07 · 云端语音（TTS）通用接入方案

> 目标：把「云端朗读」从**一次性填死**变成**跨平台可复用**的配置。
> 用户痛点原话：「配置项很多，我希望这套设置能跨平台通用。例如『音色』这一项，
> 我还得去官网介绍里逐个查找有哪些音色再填回来。」
>
> 本文基于 `语言合成api通用方案调查.txt` 的调研结论，并结合**本机实测**给出可落地方案。

---

## 0. 结论先行

**不能**靠「一套参数打天下」。只填「地址 + 模型名」只覆盖
**OpenAI 兼容的基础 TTS 子集**；一旦涉及音色、情绪、风格、流式、字幕、注音，
必然遇到平台差异——其中最硬的一条是：

> **`voice` 不是抽象概念，而是「平台/模型命名空间里的 ID」，天生不通用。**

所以正确的做法是四件事，按优先级排：

| 优先级 | 能力 | 解决什么 |
|---|---|---|
| **P1** | **音色自动发现 + 下拉选择 + 一键试听** | 直接消灭「去官网逐个查音色」← **用户这次抱怨的就是它** |
| **P1** | **能力矩阵 + 参数裁剪** | 消灭「传了平台不支持的参数 → 400」 |
| **P2** | **抽象角色 → 平台音色 ID 的映射表** | 换平台/模型时**不用改配置** |
| **P2** | **适配器插件 + `extra_body` 原始透传** | 新平台不改代码；新参数有兜底 |
| **P3** | **流式（SSE / WebSocket）适配** | 低时延场景；**音质非流式优先** |

---

## 1. 本机实测：能"自动发现"到什么程度？

用用户自己的 StepFun 账号（`https://api.stepfun.com/step_plan/v1`，`stepaudio-2.5-tts`）实测：

| 探测 | 结果 | 含义 |
|---|---|---|
| `GET /v1/models` | **200**，返回模型列表（`step-3.7-flash`、`stepaudio-2.5-chat` …） | ✅ **模型名可以自动拉**，不用手敲 |
| `GET /v1/audio/voices` | **200**，但 `{"data":[],"has_more":false}` | ⚠️ 接口形状存在、**内容为空** → 不能只依赖它 |
| `GET /v1/voices` | 404 | 非标准路径 |
| 逐个试合成 16 个候选音色名 | **8 个 200** | ✅ **探测法有效**，是官方接口为空时的可靠兜底 |

**8 个实测可用音色**（StepFun `stepaudio-2.5-tts`）：

```
cixingnansheng(磁性男声)  shenchennanyin(深沉男音)  qingniandaxuesheng(青年大学生)
qinqienvsheng(亲切女声)   wenrounvsheng(温柔女声)   ruanmengnvsheng(软萌女声)
jilingshaonlv(机灵少女)   yuanqishaonv(元气少女)
```

而 `alloy` / `echo` / `nova` / `shimmer`（OpenAI 音色名）**全部 400**
（`The voice_id (alloy) does not exist or you do not have access to it.`）。

> 结论：**「自动拉」能覆盖模型名与部分平台的音色；「拉不到」时必须内置清单 + 探测兜底。**
> 单靠任一手段都不够，必须三级降级。

## 2. 架构：三层

```
┌─────────────────────────────────────────────────────────┐
│ UI（设置页「语音」）                                       │
│  音色 = 下拉选择（角色名 + 平台 ID 双显示）+ 🔊 试听        │
└───────────────┬─────────────────────────────────────────┘
                │ 统一请求：text / voiceRole / format / speed …
┌───────────────▼─────────────────────────────────────────┐
│ 统一 TTS 层（新增 backend/services/tts_unified.py）        │
│  · 解析 provider（按 base_url 主机名自动识别）             │
│  · 查能力矩阵 → 裁剪 / 映射 / 校验参数                     │
│  · 音色解析：voiceRole → 该 model 的真实 voice ID          │
│  · 事件流统一：audio / subtitle / done / error             │
└───────────────┬─────────────────────────────────────────┘
                │
┌───────────────▼─────────────────────────────────────────┐
│ 适配器插件（backend/services/tts_adapters/）              │
│  openai.py（兜底，覆盖绝大多数 OpenAI 兼容平台）            │
│  stepfun.py（voice_label / instruction / step_plan 差异）  │
│  azure.py / minimax.py / edge.py …（按需）                 │
└─────────────────────────────────────────────────────────┘
```

### 2.1 统一请求（应用层只认这个）

```python
class TtsRequest(BaseModel):
    text: str
    voice_role: str | None = None      # 抽象角色，如 zh_female_warm ← UI 选的是它
    voice_id: str | None = None        # 平台原始 ID（高级用户 / 探测结果）
    fmt: str = "mp3"
    sample_rate: int | None = None
    speed: float | None = None
    volume: float | None = None
    emotion: str | None = None         # 由适配器决定映射到 voice_label 还是 instruction
    instruction: str | None = None
    extra_body: dict | None = None     # 原始透传，兜底新参数
```

### 2.2 能力矩阵（每 provider × model 一份）

```python
class ModelCaps(BaseModel):
    formats: list[str] = ["mp3"]
    sample_rates: list[int] = []
    speed_range: tuple[float, float] = (0.5, 2.0)
    volume_range: tuple[float, float] = (0.1, 2.0)
    max_chars: int = 1000
    supports_voice_label: bool = False
    supports_instruction: bool = False
    supports_timestamp: bool = False
    supports_sse: bool = False
    supports_websocket: bool = False
    passthrough: bool = False          # True = 不裁剪，原样透传（用户强制）
```

存放位置：**`data/tts_providers.json`（可编辑，改完不必改代码）**，
内置一份默认表；用户覆盖项另存，避免升级时被冲掉。

### 2.3 角色 → 音色 ID 映射

```jsonc
{
  "providers": {
    "stepfun": {
      "match": ["api.stepfun.com"],
      "adapter": "stepfun",
      "models": {
        "stepaudio-2.5-tts": {
          "default_voice": "cixingnansheng",
          "voice_map": {
            "zh_male_low":    "shenchennanyin",
            "zh_male_news":   "cixingnansheng",
            "zh_female_warm": "wenrounvsheng",
            "zh_female_lively": "yuanqishaonv",
            "zh_female_soft": "ruanmengnvsheng",
            "zh_youth_male":  "qingniandaxuesheng"
          },
          "caps": { "max_chars": 1000, "formats": ["mp3","wav","pcm"] }
        }
      }
    },
    "openai": {
      "match": ["api.openai.com", "*"],
      "adapter": "openai",
      "models": { "*": { "default_voice": "alloy", "voice_map": {} } }
    }
  }
}
```

**UI 里你选的是角色**（温柔女声 / 播报男声 / 活泼女声…），换平台时程序自动换成
该平台真实 ID；**没有映射就回退 `default_voice`，并在界面明确标注「该模型无此角色，已回退」**
——绝不再把无效 `voice` 直接发出去。

## 3. 音色发现的三级降级（P1 核心）

```
① 官方接口拉（GET {base}/audio/voices、{base}/voices、{base}/models）
        │ 拉到非空
        ▼
② 内置音色库（每平台一份精选清单，随版本更新；也是①为空时的兜底）
        │ 用户点「探测可用音色」
        ▼
③ 探测法：对候选清单批量试合成（只回报告状态与耗时，不返回音频）
```

- 探测结果写入本地表并缓存，**下次直接进下拉框**，不再重复试。
- 探测**必须用户手动点击才跑**（会消耗少量额度：8 个短句约几分钱），不自动跑。
- 拉/探测到的音色统一成 `{id, label, lang, gender, tags, source}`，
  `source` 标明来自 `api` / `builtin` / `probe`，UI 上可区分可信度。

### 新增接口

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` | `/api/tts/voices?refresh=0\|1` | 返回可用音色（三级降级后的并集，带 `source`） |
| `POST` | `/api/tts/voices/probe` | 对选中/全部候选批量试合成，回报告（**不返回音频**） |
| `GET` | `/api/settings/models?target=tts` | **已有能力**（现在只支持 llm/embed），补 tts 一档 |

### UI 变化（设置页「语音 → 云端」）

```
语音端点 base_url   [ https://api.stepfun.com/step_plan/v1        ]
语音模型名          [ stepaudio-2.5-tts            ] [ 拉取模型 ▾ ]
音色 voice          [ 温柔女声（zh_female_warm）    ▾ ] [ 🔊 试听 ] [ 🔍 探测可用音色 ]
                    └ 展开可见：实际发送 ID = wenrounvsheng（来源：内置库）
语音 Key            [ **************************** ]
                    [ 测试连接 ]  [ 保存语音设置 ]
当前生效：云端朗读 · api.stepfun.com/step_plan/v1
```

**音色从文本框变成下拉框**，并显示"实际会发出的 ID 与来源"——这是这一轮的重点。

## 4. 参数转换与降级（避免 400）

适配器负责五件事：

1. **只发模型支持的参数**：如 `stepaudio-2.5-tts` 不支持 `voice_label`，就不发（发了会 400）。
2. **参数映射**：`emotion="高兴"` →
   ① 支持 `voice_label.emotion` 就发它；② 否则支持 `instruction` 就转成 `instruction:"用高兴的语气说"`；
   ③ 都不支持 → 丢弃并记 WARN（或按配置报错）。
3. **范围校验**：`speed` / `volume` / `sample_rate` 超范围时截断并提示。
4. **条件校验**：如 `timestamp=true` 必须 `return_url=true` 或 `stream_format="sse"`，
   否则直接 400 —— 适配器**发送前**拦下并给出可读原因。
5. **原始透传**：`extra_body` 兜底；UI 标"高级"，并在保存时提示"参数与平台不符会直接报错"。

> **护栏**：任何被裁剪/映射/丢弃的参数，都在「测试连接 / 试听」的返回里**列出来**
> （如"已忽略：voice_label（该模型不支持）"），避免"静默改了参数"这种最难查的问题。

## 5. 流式（P3，按需）

- `synthesize_stream()` 统一事件：`{audio|subtitle|done|error}`；
- 协议差异（WS / SSE / chunked）与音频格式（PCM / Opus / MP3 分片）**由各适配器自己实现**；
- 注意 StepFun 官方提示：`stepaudio-2.5-tts` 在 WebSocket 流式下**效果可能明显低于 HTTP 非流式**，
  **无时延要求时优先非流式**。本项目的朗读是"边讲边播"，
  现有的**预取流水线**（见 `voice.js` 的 `PREFETCH`）已经把段间停顿压到 ~1ms，
  所以流式不是当前瓶颈，**建议最后做**。

## 6. 分阶段落地建议

| 阶段 | 内容 | 交付判据 |
|---|---|---|
| **P1** | 音色三级发现 + 下拉选择 + 试听 + 「探测可用音色」；能力矩阵（参数裁剪）；内置 openai/stepfun 两张清单；`/api/tts/voices`、`/api/tts/voices/probe` | 换一个 OpenAI 兼容平台，**只需填地址+Key+模型**，音色从下拉里选，不再手查官网 |
| **P2** | 角色映射表 + `tts_providers.json` 可编辑 + `extra_body` + 参数变更回显 | 换平台后**角色选择不变**，程序自动换 ID |
| **P3** | 流式适配（SSE/WS）+ 字幕事件 | 按需 |

**明确不做**：把各平台参数硬编码成"一套通用参数"——调研结论已证明必然踩坑。

---

## 7. 风险与取舍

| 风险 | 处理 |
|---|---|
| 官方 voices 接口返回空（StepFun 实测就是这样） | 内置音色库 + 探测法兜底；UI 标注来源 |
| 角色映射需要长期维护音色库 | **只覆盖主流平台**；长尾平台走「探测 + 手填」 |
| 探测消耗额度 | 仅用户点击触发；一次探测控制在 ~20 条短句内 |
| 能力矩阵写错会误裁剪参数 | 提供 `passthrough: true` 强制原样透传；被裁剪的参数一律回显 |
| 不同模型同名音色不可用 | 映射表按 **provider × model** 维度存，不跨模型复用 |
