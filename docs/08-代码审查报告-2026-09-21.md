## 三、P1 问题（建议尽快处理）

### P1-1 巨型文件，维护与回归成本高

| 文件 | 行数 | 问题 |
|---|---|---|
| `src/backend/services/courses.py` | **4,896** | 单文件 50+ 个函数，混合了大纲生成、讲义、练习、判分、预生成队列、图表编译六块领域 |
| `src/web/js/views/lesson.js` | **1,975** | 单视图文件，含渲染、事件、可视化挂载 |
| `src/web/js/views/courses.js` | **1,838** | 单视图文件，含课程 CRUD、大纲编辑、草稿恢复 |

风险：任何小改动的影响面难以静态评估；回归测试必须整文件跑；新人上手成本高。

建议（按投入产出排序，不必一次做完）：
1. `courses.py` 按领域拆分为 `courses_outline.py` / `courses_lecture.py` / `courses_practice.py` / `courses_prefetch.py`，`CourseService` 保留为门面（纯搬移，先不动逻辑）；
2. 前端两个 view 按"渲染 / 事件 / 状态"三部分拆模块。

### P1-2 文档上传全量读入内存，峰值不可控

`src/backend/routers/documents.py:43`：`data = await upload.read()` 一次性把整个文件读进内存。单文件上限 200MB（`config.max_upload_mb`），**多文件并发上传时内存峰值 = N × 200MB**。用户同时拖 10 个 100MB PDF 就会到 1GB+。

```python
data = await upload.read()   # routers/documents.py:43
```

建议：改为流式写临时文件（`shutil.copyfileobj(upload.file, tmp)` 分块 1MB），写盘过程中累计大小、超限即删并返回 `3002`；哈希也改为读盘时增量计算。接口行为（重复文件检测）不变。

### P1-3 网页抓取无响应大小限制，且无内网防护

`src/backend/services/ingest.py:159-171`：`create_from_url` 直接 `resp.text` 全量入内存，无大小上限——一个几百 MB 的页面（或恶意无限流）就能打爆内存；URL 也未限制内网地址（可抓 `http://169.254.169.254` 云元数据、`http://127.0.0.1:xxxx` 本机服务）。

```python
resp = client.get(url, headers={"User-Agent": "ZhiBan/1.0"})
html = resp.text          # services/ingest.py:162 —— 无大小限制
```

建议：抓取时流式读取并设上限（如 20MB，超出即断，返回 `3003`）；URL 做基本校验（拒绝 RFC1918 私网段、链路本地地址、`localhost`）。本地单机威胁模型下这是防御纵深，不是致命伤。

## 四、P2 问题（设计取舍 / 建议改进）

### P2-1 本地服务零鉴权

`POST /api/system/shutdown`（`routers/system.py:136`）、`/api/heartbeat` 及全部业务接口均无 token。服务绑 `127.0.0.1` 已过滤掉外部网络，但**本机任意进程、或用户浏览器里任意网页**（`fetch("http://127.0.0.1:8760/api/system/shutdown", {method:"POST"})`）都能调停服务。

建议：启动时生成一次性 token 写入 `runtime.json`，前端首次从 `/api/health` 读取，之后请求带 `X-ZhiBan-Token`。改动小，收益是把"网页静默调停本地服务"这条路堵死。

### P2-2 config.py 注释与实现不符

`src/backend/config.py:58` 注释写"host: 监听地址，固定回环地址，绝不绑 `0.0.0.0`"，但 `config.py:123` 实际是 `_env_str("ZHIBAN_HOST", "127.0.0.1")`——`.env` 里写 `ZHIBAN_HOST=0.0.0.0` 就会监听所有网卡（同一 Wi-Fi 下他人可访问资料库与模型 Key）。

建议二选一：代码层校验 host 必须为回环地址（非回环直接拒绝启动），或把注释改为"默认回环，可由 .env 覆盖（不建议）"。

### P2-3 前端无 CSP 头

`backend/main.py` 挂载静态资源但未设 `Content-Security-Policy`。当前 XSS 防线（DOMPurify/textContent/escape）有效，CSP 是漏网时的最后一层。

建议：中间件加 `Content-Security-Policy: default-src 'self'; img-src 'self' data: blob:; style-src 'self' 'unsafe-inline'`（`unsafe-inline` 是给 index.html 内联主题脚本与 KaTeX 留的，可视情况收紧）。

### P2-4 requirements.txt 依赖未全部锁死

`fastapi==0.141.1` 锁了版本，但 `uvicorn/pydantic/numpy/httpx/pypdf` 等只用 `>=`。绿色分发包到新机器 `pip install -r` 时可能拉到不兼容新版本，出现"我这能跑你那不能跑"。

建议：全部锁 `==`（或引入 `uv`/`pip-tools` 生成 lock），与"锁定版本，实测 win_amd64"的注释保持一致。

### P2-5 前端 SVG 白名单略宽松

`js/visual.js:173`：只校验 `trimmed.indexOf("<svg") === 0 && indexOf("<script") < 0`。`onload=` 等事件属性可以通过该检查（后端 `diagram.py` 已对文本 `html.escape`，当前无实际风险，但这是"依赖上游正确"的单点）。

建议：前端也过一次 `DOMPurify.sanitize(svg, {USE_PROFILES:{svg:true}})`，双防线各自独立。

### P2-6 关机用 `os._exit(0)` 可能丢末尾日志

`routers/system.py:133`：`_delayed_exit` 用 `os._exit(0)` 强制退出，跳过 atexit 与缓冲区刷写。停机前 300ms 内的日志可能丢失。WAL 已由 lifespan 的 checkpoint 保证，数据不会坏，仅日志可能缺尾。

建议：延迟从 0.3s 调到 1.0s，或退出前显式 `logging.shutdown()`。

### P2-7 FTS 查询特殊字符转义待核验

`services/retrieval.py` 的关键词通道走 FTS5 `MATCH`，查询词经 `utils/textutil.cjk_query` 转换。审查时未细看该函数是否对 FTS5 特殊语法字符（`"`、`*`、`(`、`NEAR`、`OR`）做了转义。若未转义，畸形查询可能抛 `sqlite3.OperationalError`（表现是检索 500 或降级，不是注入）。

建议：补一条用例验证 `查询词含 " 或 *` 时的行为；`list_documents` 的 LIKE 通道（`ingest.py:331`）已参数化，无此问题。
